The Real-World Analogy: A Hospital

Forget finance for a moment. Imagine a hospital emergency room.

  • A patient walks in with symptoms — the user's request
  • The triage nurse reads the symptoms and decides which doctors are needed — the router
  • The hospital coordinator schedules and sequences the doctors — the orchestrator
  • Each doctor examines the patient independently — the agents
  • A shared patient chart is updated after every doctor visit — the state
  • Hospital safety rules ensure no doctor is overwhelmed — resilience
  • Audit logs record every action for accountability — monitoring

This entire project is that hospital — but for financial questions.

1. Business Functionality

What does this system actually do?

A user asks a financial question. The system routes it to the right AI specialists:

"Should I buy AAPL stock, and what are the tax implications
 on my $100k portfolio with moderate risk tolerance?"
         │
         ├──► Equity Agent  → "AAPL looks bullish. BUY with 80% confidence."
         ├──► Tax Agent     → "Selling triggers short-term gains. Hold 1 year to save ~$3,000."
         └──► Risk Agent    → "Your portfolio is moderately aggressive. Consider bonds."

The user gets three expert opinions in one call. This is the business value.

2. Orchestration — "The Hospital Coordinator"

File: src/orchestrator_langgraph.py

The orchestrator is the traffic controller. It doesn't do any analysis itself — it just manages the flow:

Step 1: Receive the request
Step 2: Create a shared "notepad" (state) for all agents to read/write
Step 3: Ask the router → "Which agents do we need?"
Step 4: Call Agent 1, wait for result, save it to the notepad
Step 5: Call Agent 2, wait for result, save it
Step 6: Call Agent 3, wait for result, save it
Step 7: Bundle all results → return to user

The key tool it uses is LangGraph's StateGraph — think of it as a flowchart you can execute in code:

workflow = StateGraph(AgentState)       # Create the flowchart
workflow.add_node("equity_expert", ...) # Add a box
workflow.add_node("tax_expert", ...)    # Add another box
workflow.add_edge("equity_expert", ...) # Draw an arrow between boxes
compiled = workflow.compile()           # Lock it in
result = compiled.invoke(initial_state) # Run it

3. State Management — "The Shared Notepad"

File: src/models/langgraph_state.py

Imagine every doctor in the hospital shares one patient chart. Doctor A writes their findings, Doctor B reads them before seeing the patient. That chart is AgentState.

AgentState = {
    "request":       { who asked, what they want },   # Written once at start
    "workflow_type": "COMPREHENSIVE_ANALYSIS",         # Written once by router
    "agent_results": {                                 # Each agent writes here
        "equity_expert": { "recommendation": "BUY" },
        "tax_expert":    { "advice": "Hold 1 year" },
        "risk_expert":   { "score": 6.2 }
    },
    "status":  "RUNNING → COMPLETED",                 # Updated as we go
    "errors":  []                                      # Any failures logged here
}

Why not just pass data directly agent-to-agent?
Because agents don't know about each other. The state is the only thing they share. This keeps them independent — you can add, remove, or swap agents without changing anything else.

Checkpointing means LangGraph saves this state after every step to memory. If something crashes, you can see exactly where it stopped. Advanced: you can rewind to any checkpoint and re-run from that point.

4. Deterministic Routing — "The Triage Nurse's Rulebook"

File: src/workflows/deterministic_router.py

This is the most important design decision in the whole project.

The Bad Way (standard LangGraph)

Ask the AI: "What should we do next?"
AI says: "Call the equity agent"        ← maybe right
AI says: "Call the equity agent again"  ← wrong, loops forever

The Good Way (this project)

# Simple Python rules — always correct, always predictable
if has_stocks and has_tax and has_risk:
    return COMPREHENSIVE_ANALYSIS    # → call all 3 agents

elif has_stocks and has_risk:
    return PORTFOLIO_REVIEW          # → call equity + risk

elif has_stocks:
    return EQUITY_ANALYSIS           # → call equity only

No AI involved in routing. It's just an if-statement. The routing decision is made once at the start based on what's in the request. After that, the orchestrator just ticks agents off a checklist.

The pre-defined checklists live here:

WORKFLOW_DEFINITIONS = {
    WorkflowType.COMPREHENSIVE_ANALYSIS: [
        "equity_expert",   # Step 1
        "tax_expert",      # Step 2
        "risk_expert"      # Step 3
    ]
}

5. The Agents — "The Specialist Doctors"

Files: src/agents/

Each agent follows the same pattern — like doctors who all went to the same medical school:

class EquityAgent(BaseLangGraphAgent):

    def validate_input(self, state):
        # "Do I have what I need to do my job?"
        return state["request"].stocks is not None

    def get_system_prompt(self):
        # "What kind of expert am I?"
        return "You are a senior equity analyst at a top investment bank..."

    def process_request(self, state):
        # "Here's my analysis"
        # Builds a prompt, calls OpenAI, returns structured result
        response = self.llm.invoke(prompt)
        return { "recommendation": "BUY", "confidence": 0.85 }

The base class (base_agent.py) handles everything else automatically:

  • Calling the LLM
  • Retrying if it fails
  • Timing out if it takes too long
  • Recording how long it took
  • Logging input and output

The specialist agents only care about their domain — they don't think about retries or timeouts at all.

6. Resilience — "The Hospital Safety Rules"

File: src/utils/resilience.py

Three patterns protect the system from failures:

Circuit Breaker — "Stop calling a doctor who's unavailable"

Normal: call OpenAI → works ✅
        call OpenAI → works ✅
        call OpenAI → fails ❌
        call OpenAI → fails ❌
        call OpenAI → fails ❌  →  CIRCUIT OPENS

Circuit open: call OpenAI → BLOCKED immediately ⛔ (don't even try)
              wait 30 seconds...
              one test call → works ✅ → CIRCUIT CLOSES → back to normal

Without this, every request waits for the full 30-second timeout when OpenAI is down. With it, failures are instant and the system recovers automatically.

Retry with Backoff — "Try again, but wait a bit"

Attempt 1 → fails (network blip) → wait 1 second
Attempt 2 → fails (still flaky)  → wait 2 seconds
Attempt 3 → succeeds ✅

Most temporary failures fix themselves within seconds. Retrying silently handles them.

Timeout — "Don't wait forever"

Agent call starts → 30 seconds pass → cancelled → error returned

Without timeouts, one stuck API call blocks the entire workflow indefinitely.

7. Monitoring — "The Audit Trail"

File: src/utils/monitoring.py

Every significant event is logged as structured JSON:

{ "event": "agent_started",   "agent": "equity_expert", "timestamp": "10:30:00" }
{ "event": "agent_completed", "agent": "equity_expert", "execution_time": 2.3 }
{ "event": "agent_started",   "agent": "tax_expert",    "timestamp": "10:30:02" }

Why structured JSON instead of plain text?

Plain TextStructured JSON
"Equity agent finished"{ "agent": "equity_expert", "execution_time": 2.3 }
Can't search or analyzeCan query, filter, aggregate, chart

With structured logs you can answer questions like:

  • Which agent is slowest on average?
  • How often does the risk agent fail?
  • What was happening when user X got an error?

Metrics (counts and timings) are also collected in Prometheus format — tools like Grafana can visualize these as live dashboards.

The Big Picture — How It All Connects

User Request
    │
    ▼  [Pydantic validates: is this data valid?]
    │
    ▼  [Router: what type of workflow is this?]    ← deterministic_router.py
    │
    ▼  [Orchestrator creates State, runs graph]    ← orchestrator_langgraph.py
    │
    ├──► Agent 1                                   ← agents/equity_agent.py
    │       ├── validate input
    │       ├── call OpenAI  ← protected by circuit breaker + retry + timeout
    │       ├── write result to State
    │       └── log everything
    │
    ├──► Agent 2 (reads State, writes State)
    ├──► Agent 3 (reads State, writes State)
    │
    ▼  [State checkpointed at every step]          ← LangGraph
    │
    ▼  [Final result formatted and returned]
